# CLAUDE.md

This file provides guidance when working with code in this repository.

## Project

`sbmlutils` is a python library for models in the Systems Biology Markup Language (SBML), built on libsbml: model creation from a python definition, annotation, validation, reports, converters and support for the `comp`, `fbc`, `distrib` and `layout` packages. Pure library, no CLI entry points. Requires python >= 3.11, packaged with hatchling (version is read from `src/sbmlutils/__init__.py`). Runtime dependencies are `python-libsbml` and `antimony` (SBML), `pymetadata` (annotations and COMBINE archives), `pint`, `numpy`, `pandas`, `rich`, `lxml`, `jinja2`, `markdown-it-py`, `xmltodict`, `openpyxl` and `requests`. The package neither simulates nor plots: `libroadrunner`, `matplotlib` and `scipy` (the integrator of the python code the ODE export writes) are the `examples` extra, `py4cytoscape` the `cytoscape` extra and `cobra` the `cobra` extra; `dev` pulls in `cytoscape` and `examples`.

## Commands

```bash
# environment (uv based)
uv sync --extra dev
uv run pre-commit install
uv lock                                       # after every change of a dependency in pyproject.toml

# tests
pytest                                        # all tests
pytest tests/test_factory.py                  # single file
pytest tests/test_factory.py::test_model_units  # single test
tox r -e py3.14                               # single tox env (py3.11-3.15 available)
tox r -e py3.14 -- tests/test_factory.py      # one file in that env, `--` passes through to pytest
tox r -e cobra                                # the tests which need cobrapy, on python 3.14
tox r -e lowest                               # the suite against the lower bounds of the dependencies, on python 3.11
tox run-parallel                              # full matrix + ty + cobra + lowest
tox r -e julia                                # the generated julia code, needs julia (SBMLUTILS_JULIA)
tox r -e R                                    # the generated R code, needs Rscript and deSolve (SBMLUTILS_RSCRIPT)
tox r -e latex                                # the ODE documents compiled, needs tectonic
python scripts/ode_report.py                  # ODE export over the SBML test suite, `--format julia --format r`

# lint / format / types
ruff check
ruff format
tox -e ty                       # ty type check (config in [tool.ty] in pyproject.toml)
uvx ty check                    # same check, straight from the working tree

# examples, they are modules of the `examples` package and not part of sbmlutils
python -m examples.species
python -m examples.tutorial.minimal_model
python -m examples.converters.ode docs/images/ode   # the ODE export files the docs show, run before `zensical serve`
```

Julia and R run the code of the ODE export through the command prefixes in `SBMLUTILS_JULIA` (default `julia`) and `SBMLUTILS_RSCRIPT` (default `Rscript`), split with `shlex`; their tests skip when the command does not run, and fail instead with `SBMLUTILS_REQUIRE_TOOLCHAINS=1`, which the tox environments `julia`, `R` and `latex` set. Julia needs the packages of `tests/converters/ode/julia/Project.toml` (`julia --project=tests/converters/ode/julia -e 'using Pkg; Pkg.instantiate()'`, then `JULIA_PROJECT` pointing at it), R the package deSolve. Neither has to be installed, docker works: `SBMLUTILS_JULIA="docker run --rm -v /tmp:/tmp -v $HOME/.julia-docker:/root/.julia -e JULIA_LOAD_PATH=@:@stdlib julia:1.11 julia --project=@sbmlutils-ode"` with that project instantiated as the shared environment `@sbmlutils-ode` of the depot, and `SBMLUTILS_RSCRIPT="docker run --rm -v /tmp:/tmp sbmlutils-r Rscript"` with the image of `tests/converters/ode/docker/r.Dockerfile` (`docker build -t sbmlutils-r -f tests/converters/ode/docker/r.Dockerfile tests/converters/ode/docker`); the jobs run under `/tmp`, which the containers mount.

`develop` is the default branch and takes every change through a pull request; direct pushes are rejected by the rulesets in `.github/rulesets/` (applied with `.github/rulesets/apply.sh`), which require the `tests`, `ruff`, `ty` and `docs` checks. `main` only tracks the latest release and is fast-forwarded by the `sync-main` job of the release workflow, never by hand.

Release steps are in `docs/development.md` (there is no separate `RELEASE.md`): the release is prepared on a branch, `uvx bump-my-version bump [major|minor|patch]` updates `src/sbmlutils/__init__.py` and `CITATION.cff` and commits without tagging (`tag = false`, a squash merge would rewrite the commit), and the tag is created on `develop` after the pull request was merged, which triggers the PyPI release workflow.

Documentation is [Zensical](https://zensical.org/): markdown sources in `docs/`, configured in `zensical.toml`, built into the gitignored `site/` (`uv run zensical build --clean`, `uv run zensical serve` for the preview). The API reference is rendered from the docstrings by mkdocstrings; a page in `docs/api/` is just `::: sbmlutils.<module>`, so nothing is generated into the repository. Math (`$...$`, `$$...$$`) is typeset by MathJax through `pymdownx.arithmatex`, vendored in `docs/javascripts/mathjax/` with its fonts, `--8<-- "images/ode/repressilator.py"` includes a file of `docs/` with `pymdownx.snippets`, and the `exclude` plugin keeps `docs/superpowers/` (internal design documents) and the included markdown of `docs/images/ode/` out of the pages. `docs/images/ode/` holds the output of the ODE export of the repressilator which `docs/ode.md` shows, written by `python -m examples.converters.ode docs/images/ode`: the text files are committed and kept current by `tests/converters/ode/test_ode_docs.py`, the SVG pages of the typst document are gitignored and compiled by that command, which the `documentation` workflow runs before the build and which has to run before a local `zensical build` or `zensical serve`; ruff and the whitespace hooks leave the directory alone. `scripts/llms_txt.py` runs after the build and writes the agent facing files (`llms.txt`, `llms-full.txt` and the markdown of every page, snippets included) into `site/`. The `documentation` workflow runs both and publishes the site from `develop`.

## Architecture

**`factory/` - the model definition.** The main package, 8700 lines and the entry point of the library. `sbmlutils.factory` is a facade: `factory/__init__.py` re-exports the names of its modules, and `from sbmlutils.factory import *`, which every model definition uses, gives the names of its `__all__`. The modules follow the SBML packages and import each other without cycles in this order: `_core` (`Sbase`, `KeyValuePair`, `Value`, the loss reports and the helpers the elements share), `units` (`Unit`, `UnitDefinition`, `Units`, `ModelUnits`, `ValueWithUnit`), `core_elements` (the elements of SBML core), `distrib`, `fbc`, `comp`, and `model` (`Model`, `ModelDefinition`, `Document`, `create_model`); a module imports a later one only for the type checker, under `TYPE_CHECKING`. The API reference lists the re-exported classes and functions in `members` of `docs/api/factory.md`, `tests/test_factory_facade.py` pins the names and checks that list. A model is a `Model` holding `Compartment`, `Species`, `Parameter`, `Reaction`, rule, event and package objects; `create_model(model, filepath)` walks them, calls `create_sbml` on each and writes the validated SBML. Every element derives from `Sbase`, which carries `sid`, `name`, `metaId`, `sboTerm`, `notes`, `annotations`, `port`, `uncertainties` and `keyValuePairs`, and implements the two-step creation: `create_sbml(model)` creates the libsbml object, `_set_fields` sets the attributes on it. `Sbase._set_fields` declares both parameters as `Any` on purpose: every concrete subclass narrows the created object to the one libsbml type it creates, and only a `Document` is set without a model, so a precise base signature would make every override an LSP violation. Annotations are accepted as a `Sequence` (covariant) and stored as a `list`, so a model definition can pass its natural `list[tuple[BQB, str]]` and still append afterwards. `Units` is the base of the unit class of a model: a `UnitDefinition` parses an expression like `mmole/min/l` with pint and writes the SBML unit definition; the id of a definition must not be an SBML base unit kind (`UnitDefinition("litre")` is invalid, `UnitDefinition("l", "liter")` is not). `ModelDefinition` is a `Model` and is filled by the same `Model._fill_sbml`, which states the rule every element writer follows: the model being filled is handed down, never fetched, because libsbml answers `getModel()` of an element inside a `<comp:modelDefinition>` with the model of the *document*, so an element which reaches for its own model resolves the ids of its math against the wrong one and the document still validates.

**`io/sbml.py`, `validation.py` - reading, writing, checking.** `read_sbml` accepts a path or an SBML string and raises a `ValueError` for a source it cannot read, `write_sbml` writes a file or returns the string. `validate_sbml`/`validate_doc` run the libsbml consistency checks configured by `ValidationOptions` (all on by default, the unit check is the expensive one) and return a `ValidationResult` with the errors and warnings. Validation reports, it never blocks: `create_model` writes the file either way. `check()` wraps a libsbml call, which returns a status code instead of raising. `ScopedLossCollector` is for the losses which repeat: an annotation resource pymetadata cannot canonicalize, an attribute the level and version of the document has no place for. Inside the scope of one document every such loss is collected under a key and reported once when the scope ends; the collection lives in a `ContextVar`, so writing one document never collects into the report of another.

**`parser.py` - the inverse direction.** `sbml_to_model` reads an SBML file back into the `Model` of `sbmlutils.factory`, `antimony_to_sbml`/`antimony_to_model` do the same for antimony. The module docstring lists exactly what is read and what is not. `_parse_model_body` holds the body of the work and takes any `libsbml.Model`: a `<comp:modelDefinition>` is read by constructing a `ModelDefinition` and recursing into that same function, so everything of every package inside it is read as it is for the model of the document. `_parse_fbc_model` and `_parse_comp_model` read the package content of a model, `_parse_comp_document` the model definitions of the document, `_convert_fbc_v1` brings an fbc version 1 document to version 2 before it is read. What libsbml reads and the factory has no field for is dropped by a named `_drop_*` helper (`_drop_uncertainties`, `_drop_replaced_by`, `_drop_unwritable`), which reports the loss where the element is still known rather than handing the writer something it loses in silence.

**`report/sbmlinfo.py` - the content of a model.** `SBMLDocumentInfo` walks a document and produces the dictionary the sbml4humans report renders: every element with its equation as a readable string, its math as latex (`report/mathml.py`), its unit as `mmol/min/l` (`report/units.py`) and its annotations. Every element gets a primary key built from its id, else its metaId, else its place in the list of its owner (nothing is cached on the libsbml object, libsbml returns a new proxy from every getter), so the report can link between elements. The frontend and the http api which serve this live in [matthiaskoenig/sbml4humans](https://github.com/matthiaskoenig/sbml4humans), they were moved out of this repository in 0.10.0; `report/sbmlreport.py` stays, it is the client which opens a model on an sbml4humans running on the same machine, since the model is served on the loopback address only.

**`comp/`, `fbc/`, `layout/`, `manipulation/` - the packages.** `comp.flatten_sbml` resolves the submodels of a hierarchical model into a flat one (libsbml resolves an external model definition relative to the location of the document, which `read_sbml` sets to the absolute path, so the working directory is never changed). `manipulation.merge_models` combines several models into one comp model, which is what `create_model` does with several definitions. `fbc/cobra.py` is the bridge to cobrapy, which is optional and therefore imported in a `try`/`except`, with `cobra = None` as the fallback the tests skip on.

**`converters/` - SBML into something else.** `ode/` exports the system of ordinary differential equations of a model in six formats: code which simulates it (python with a `scipy.integrate` solver, julia with OrdinaryDiffEq, R with deSolve, option `simulator`) and documents which describe it (typst, LaTeX, markdown, options `standalone` and `symbols`). It has three layers which know nothing of each other: the analysis (`system.py`, `analysis.py`, `dependencies.py`, `events.py`, and `astutil.py` with the helpers for building and reading the libsbml math they share) resolves the SBML semantics once into the frozen `OdeSystem` (states, constants, assignments in dependency order, initial values, events with their root functions, `unsupported` constructs), as libroadrunner implements them; the printers (`printers/`) write libsbml math in a dialect per language on the engine of `printers/base.py`, identifiers only from a symbol mapping (`symbols.py`); the formats (`formats.py`, `documents.py`, the jinja2 templates in `resources/converters/ode/`) render a context of plain strings, so a template never touches libsbml. Every free text goes through `text.py` (single line, escaped per format) and every id is checked to be an SId. The numerical code is verified against libroadrunner over the SBML semantic test suite: a curated subset in the default run (`tests/converters/ode/test_ode_testsuite.py`), the full sweep behind the `sbml_testsuite` marker and in `scripts/ode_report.py`, whose pass rates `docs/ode.md` publishes; `create_model(create_markdown=True)` writes its markdown. `xpp.py` converts XPP/XPPAUT ode files to SBML; `copasi.py` writes the ids into the names.

**`data/interpolation.py`** turns a table of data points into an SBML model whose assignment rules evaluate a constant, linear or cubic spline interpolation.

**The package round trip is verified in three layers**, because roadrunner refuses fbc, ignores distrib and flattens comp, and a document stripped of all three validates. `tests/structural.py` is layer 1 and is the comparison policy: its module docstring is the policy, the code implements it and nothing else, and every package round-trip test is judged by it. `WHITELIST` holds exactly three normalizations which preserve the meaning (a gene product association flattened by libsbml, a `<cn>` gaining `type="integer"`, an annotation resource canonicalized to its compact identifiers.org URL); nothing else is ever treated as equal. `scripts/package_report.py` sweeps the corpus with it, one process per case, as `scripts/roundtrip_report.py` does for simulation. `tests/test_package_semantics.py` is layers 2 and 3: comp by flattening both documents with `flatten_sbml` and simulating them, fbc by reading both as constraint based models with cobrapy, which is what the tox `cobra` environment exists for.

`console.py` (rich console, for scripts and examples) and `log.py` provide the shared output/logging. Modules get their logger from the standard library with `logging.getLogger(__name__)`. The package never configures logging: no handlers, no levels, only a `NullHandler` on the `sbmlutils` logger; `log.enable_rich_logging()` is the opt-in for scripts. Library code logs, it does not print, and log calls use lazy `%s` formatting rather than f-strings (enforced by ruff `G`).

## Conventions

- Type checking is done with [ty](https://docs.astral.sh/ty/) (mypy was removed in 0.10.0). `[tool.ty.terminal] error-on-warning = true` means warnings fail the check, so the tree must stay at zero diagnostics; the checked python version is inferred from `project.requires-python`. Suppress a diagnostic with a rule-specific `# ty: ignore[rule-name]`, never a blanket `# type: ignore`. ty also runs as a pre-commit hook (`--extra dev`).
- libsbml has no type stubs and builds its objects through SWIG, so annotate the libsbml objects explicitly and use the getters (`getVariable()`) rather than the attributes SWIG synthesizes (`variable`), which the type checker cannot see.
- Every module, class and function carries full type annotations and a docstring. New docstrings are google style, older ones still use the `:param:` form.
- `examples/` at the top level holds the runnable examples, they are not part of the package and are run as modules (`python -m examples.species`). A model definition imports the names of `sbmlutils.factory` with a star import, which is the documented style, so `F403`/`F405` are ignored for `examples/` and `tests/`. An example writes into the current working directory and never opens a window: a plotting example saves its figure to a file, and the `conftest.py` at the root selects the `Agg` backend for the test session.
- Test fixtures and the packaged models live in `src/sbmlutils/resources/`; `resources/__init__.py` names them. `API_EXAMPLES_MODEL` and `API_EXAMPLES_OMEX` are used by the sbml4humans api. The SBML test suite and the biomodels archives under `resources/models/` are 77 MB of test data and are excluded from the distribution, see `[tool.hatch.build]` in `pyproject.toml`, so a test which reads them resolves them from the repository (`tests/test_parser.py`) rather than from the installed package.
- An optional dependency is imported behind `if TYPE_CHECKING: ... else: try/except ImportError`, with `None` as the fallback the code checks, see `fbc/cobra.py` and `cytoscape.py`. The tox `ty` environment installs the `cytoscape` and `examples` extras and `typst` (which the tests compile the typst documents of the ODE export with) so those imports resolve for the type check; `cobra` is deliberately not installed, which is why its import carries a `# ty: ignore[unresolved-import]`. A test which needs an optional dependency skips without it, so the tox `cobra` environment, pinned to python 3.14 and part of `envlist`, is what runs the tests which need cobrapy (`tests/test_package_semantics.py` and `tests/fbc/test_cobra.py`); they would otherwise skip everywhere and verify nothing.
- Markdown carries no hard line wraps: a paragraph, a list item or a table row is a single line and the wrapping is left to the editor. Code fences, headings and the rows of badges keep their line structure.
- `uv.lock` is committed and pins the local development environment (`uv sync`, `uv run`, so also `uv run ty check`) and the `documentation` workflow, which runs `uv sync --locked`; the tox environments, i.e. the test matrix and the `ty` check of continuous integration, resolve from `pyproject.toml` and do not use it. After changing a dependency in `pyproject.toml` run `uv lock`, otherwise the `documentation` workflow fails. The lower bounds of the dependencies are tested by the tox `lowest` environment, change one only together with a run of it; `lowest-overrides.txt` pins `rich`, `requests` and `markdown-it-py` to their bounds there, because `pymetadata` requires newer releases of them, so keep it equal to the bounds. The sdist holds only what builds and tests the package (`only-include` in `pyproject.toml`), the wheel ships `py.typed`.
- Release notes go in `release-notes/` as part of a release commit.
