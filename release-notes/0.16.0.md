# Release notes for sbmlutils 0.16.0
![sbmlutils](https://github.com/matthiaskoenig/sbmlutils/raw/develop/docs/images/sbmlutils-logo-60.png)

We are pleased to release the next version of sbmlutils including the following changes. Measured data drives a model: an interpolation of the data replaces quantities of an existing model in place, through a comp model which leaves the original untouched, or in a model definition (#16, #500).

## New features
- `FactoryResult.validation` exposes the validation result of the final file, after annotations; `create_model(raise_on_error=True)` raises on validation errors while leaving the file available for diagnosis
- `ValidationOptions.fast()` keeps structural checks and skips unit analysis
- reports can skip derived units, XML and LaTeX with `include_derived_units`, `include_xml` and `include_math`; `write_json` writes to a path or text stream without allocating the complete JSON string
- reading and validation accept optional `max_bytes` limits on decompressed input and `allow_external_models=False` to reject external comp references before validation
- `Interpolation.drive` drives a parameter, species or compartment of an existing model with the interpolated data, in place; x is the time or a quantity of the model, `targets` maps a column to the element it drives (#16, #500)
- `Interpolation.drive_comp` drives a model through a comp model which references the original, or embeds it with `embed=True`; flattened it simulates as the model driven in place (#16, #500)
- `Interpolation.assignment_rules` gives the interpolation as assignment rules of a model definition (#16, #500)

## Breaking changes
- model creation applies spreadsheet annotations before writing and validating the final file; an annotation failure no longer leaves an intermediate, unannotated output file
- Antimony conversions release their loaded models after each call and serialize access to the native registry; applications using Antimony directly must coordinate that access or use separate processes
- merge identifiers must be valid SBML IDs, and BioModels identifiers must contain only ASCII letters, digits, `_` or `-`; output paths which resolve outside their directory are rejected
- linear and cubic spline interpolation hold the first value before and the last value after the data, instead of `0.0` (#16, #500)
- data which cannot be interpolated raises a `ValueError` instead of a warning: fewer than 2 columns or data points (3 for the cubic spline), column names which are not strings or repeat, a first column which is not an SBML id, a column which is not numeric, a missing or infinite value, x which repeats (#16, #500)
- `Interpolation.add_interpolator_to_model` is removed, `drive` replaces it; `Interpolation.create_interpolators` is the property `Interpolation.interpolators`; the attributes `doc` and `model` of an `Interpolation` are removed (#16, #500)
- the standalone model of an interpolation is SBML L3V2 with a port on every interpolated parameter and on x, its notes name the data and the method (#16, #500)

## Fixes
- report JSON preserves zero values and false flags, including a neutral FBC species charge; initial assignments without math no longer crash report generation
- primary keys of unnamed report elements use a traversal-local list index, avoiding quadratic scans
- Level 3 parameter units are resolved from their declarations without whole-model unit analysis, with a cache scoped to each model and traversal
- namespace-prefixed and malformed XML strings are recognized as content, and documented string filenames no longer log an error
- `ValidationOptions(modeling_practice=False)` disables the modeling-practice checks
- ordinary IO, factory and parser imports no longer load Antimony or the ODE exporter until a conversion requests them
- Python 3.12 and minimum direct dependency versions are included in CI; a fresh-process performance report measures imports, validation, reports and native peak memory

## Documentation
- the guide [Interpolation](https://matthiaskoenig.github.io/sbmlutils/interpolation/) covers driving a model in place, through comp and in a model definition, and its code is run by the tests; the example `examples.interpolation.driving` drives a model of glucose uptake with measured plasma glucose, `examples.interpolation.pancreas` drives a dose response (#16, #500)

- Model creation returns immutable, grouped construction diagnostics separately
  from final validation. Opt-in `strict=True` rejects reported input losses,
  failed checked libSBML operations, and undeclared rule/initial-assignment
  targets before writing, preserving an existing output file. The default
  continues to create missing target parameters. `ConstructionError` exposes
  the findings; annotation resources retained verbatim are informational.

- The SBML parser reports grouped known round-trip losses through
  `Model.preservation_diagnostics`. Factory results carry these independently
  from construction and validation findings, including after merging models.
  Opt-in `strict_preservation=True` on parsing or model creation raises
  `PreservationError`; a strict write rejects known source losses before
  touching its destination. Default parsing and writing remain permissive.
