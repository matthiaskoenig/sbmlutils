# Release notes for sbmlutils 0.17.3
![sbmlutils](https://github.com/matthiaskoenig/sbmlutils/raw/develop/docs/images/sbmlutils-logo-60.png)

We are pleased to release the next version of sbmlutils including the following changes. This release is the libraries of the day: the ODE export reads the wide math of a model without recursion, and the COMBINE archives are read and written by the Rust core of pymetadata.

## Dependencies

- `sbmlode>=0.3.3`, which `sbmlutils.converters.ode` re-exports module for module. libsbml reads the flat n-ary sum of a MathML document as a chain of binary nodes, so an assignment rule which sums 1,200 parameters is math 1,200 levels deep: the documents of such a model failed with a `RecursionError` and dropping the zero terms of such a sum copied the square of its length in nodes (a sum of 5,000 terms took 23 seconds and 14 GB). The printers and the walks of `astutil` carry a stack of their own now, a chain of 20,000 terms renders in every format in under a second, and math which nests genuinely deeper than the printers can read is refused with an `UnsupportedMathError` which names the depth and the element instead of a `RecursionError`.
- `pymetadata>=0.9.0`, whose `pymetadata.omex` reads and writes COMBINE archives through the Rust `pymetadata-core`. The public API of `Omex`, `Manifest` and `ManifestEntry` is unchanged and `sbmlutils.biomodels` reads the archives of BioModels as before; reading is lazy and a member which nobody touched is copied compressed, so an archive is read and written several times faster. The bytes of a written archive change where its content does not: the `manifest.xml` is serialized by the core (no `master="false"` attribute, a single quoted XML declaration) and a member which is written anew carries the zip epoch as its modification time, which makes a written archive reproducible. pymetadata is no longer pure python, see its [installation](https://matthiaskoenig.github.io/pymetadata/installation/) for the platforms which have a wheel.
