# Release notes for sbmlutils 0.19.0

ODE exports use the shared Rust generator in sbmlsim-core 0.36.0. The factory's `create_model(create_markdown=True)` and the deprecated converter namespace use the same analysis, printers and templates as sbmlsim and sbml4humans. sbmlode is no longer a dependency.

- Import `OdeSystem` from `sbmlsim_core`. It exports Python, Diffrax/JAX, Julia, R, Markdown, LaTeX and Typst from original SBML bytes, XML text or trusted paths.
- The deprecated `sbmlutils.converters.ode` namespace retains its six public aliases and `system`/`formats` imports. Former Python printer implementation modules are no longer re-exported; mathematical code now belongs to Rust.
- Original SBML bytes retain full double precision. Trusted local comp documents resolve through the shared native reader; untrusted callers supply companion documents explicitly.
- Examples and documentation use the shared public API. The complete supported Python matrix, minimum dependency environment and type checks pass against the migrated generator.

## Migration of typed equation consumers

`OdeSystem.typeset()` now returns JSON-compatible linked LaTeX data owned by the Rust core, rather than the former Python dataclasses. Dataclass inspection and printer implementation APIs are not retained. Read original XML bytes, XML text or a path with `from_sbml`; pass a factory's written SBML path instead of a live libSBML document. `render` and `write` retain the ordinary code/document workflow and target options. Custom templates use MiniJinja with the shared context and embedded format templates; Python callbacks and arbitrary filesystem includes are not available.
